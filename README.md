# Infrastructure Engineering

Practical notes, templates and anonymised case studies from system administration and
infrastructure work.

> All case studies are anonymised: no employer names, internal IP addresses, domain names,
> hostnames, configurations or logs. Material is published only when it does not break
> the employer's rules.

## Structure

| Section | Topics | Status |
|---|---|---|
| [case-studies/](case-studies/) | Troubleshooting and incident write-ups | 1 case study |

Planned sections (created only when there is real content for them):

- `virtualization/`: VMware and virtualization
- `windows-server/`: Active Directory, Group Policy, PowerShell
- `linux/`: Linux, Nginx, HAProxy, Ansible
- `networking/`: L2/L3 and network diagnostics
- `monitoring/`: monitoring and observability
- `security-hardening/`: infrastructure security and hardening
- `troubleshooting/`: diagnostic checklists and runbooks

## How case studies are written

Every case study follows [case-studies/CASE-STUDY-TEMPLATE.md](case-studies/CASE-STUDY-TEMPLATE.md):
context → symptoms → diagnostics → root cause → solution → verification → lessons learned.
